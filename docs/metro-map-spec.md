# 地下鉄学習マップ 仕様・指示書

コーディングエージェント（Claude Code または Codex）に渡す指示書。この文書だけで着手できるように書いている。不明点は推測で埋めず、「未確定事項」に挙げた前提で進め、判断した内容を README に残すこと。

## 1. 目的

中国の都市の地下鉄について、主要エリアの駅と、路線の全体形を頭に入れるための学習用ページを作る。乗換案内や旅行計画の機能は持たない。

対象都市は上海から始め、広州、深圳、香港を順に追加する。都市の追加はデータファイルの追加だけで済む構造にする。

## 2. 完成形

- 実際の地図の上に、地下鉄の路線が路線色の線で、駅が点で表示される。
- 駅にマウスを乗せる（タッチ端末ではタップする）と、次の内容が出る。
  - 駅名の原表記 ／ 日本の漢字表記 ／ 読み方
  - その駅を通る路線の番号（または路線名）。各路線の色のバッジで示す。
- 画面上で都市を切り替えられる。
- PC のブラウザを主対象とし、iPad と iPhone の Safari でも同じ URL で使える。

## 3. 表示仕様

### 3.1 地図
- 背景は地名ラベルのない淡色の地図を既定にする（路線と駅を目立たせるため）。ラベル付きの標準地図に切り替えられるようにする。
- 地図タイルは OpenStreetMap 系の公開タイルを使う。各タイルの利用規約と出典表示に従う。
- 初期表示は都市ごとの「主要エリア」。全域表示に切り替えるボタンを置く。

### 3.2 路線
- 線形は実際の線路の形に沿わせる（駅間を直線で結ばない）。
- 色は路線の公式色。線の太さはズームに応じて読みやすく保つ。
- 凡例（色と路線番号・路線名）を置き、路線ごとに表示・非表示を切り替えられる。

### 3.3 駅
- 駅は 1 駅 1 点。乗換駅は複数路線の駅を 1 点に統合し、見た目で区別できるようにする（大きめの白抜きなど）。
- ホバーまたはタップで出す内容は次のとおり。これ以外は出さない。

```
陆家嘴 ／ 陸家嘴
Lùjiāzuǐ（ルージャーズイ）
[2] [14]        ← 各路線色のバッジ
```

- 一定以上に拡大したときは、日本の漢字表記を駅の横に常時表示する。表示する表記（原表記・日本漢字・両方・なし）は切り替えられる。
- 緯度・経度は内部で保持するだけで、画面には出さない。

### 3.4 入れないもの
- ホテル、観光地、旅程など、特定の旅行に関わるデータ
- 経路検索、所要時間、運賃、時刻

## 4. 読みと表記の方針

| 都市 | 原表記 | 読み | 読みの形式 |
|---|---|---|---|
| 上海・広州・深圳 | 簡体字 | 普通話 | 声調付きピンイン＋カタカナ |
| 香港 | 繁体字 | 広東語 | 粤拼（Jyutping）＋カタカナ |

- 日本の漢字表記は、原表記を日本の新字体に置き換えたもの。日本に対応する字がない場合は元の字のまま残す（例：嘴、址）。
- 香港は英語の公式駅名も内部で保持する（表示は任意の切替項目）。
- ピンインは固有名部分を続け書きし、路・大道・方位（东南西北中）・公园・博物馆などの通名は分かち書きにする。語頭は大文字。付録 A の書き方に合わせる。
- カタカナは近似でよいが、規則を一貫させる。付録 A の表記を正とし、変換表はこれに合わせて作る（例：路 Lù→ルー、科 kē→コー、车 chē→チョー、衡 héng→ホン、zh・j→ジ系、ch・q→チ系、sh・x→シ系、単母音の開音節は長音）。

## 5. データ仕様

都市ごとに 1 ファイル（`data/<city_id>.json`）とし、都市一覧を `data/cities.json` に持つ。表示ページはこの 2 種類だけを読む。

```json
{
  "id": "shanghai",
  "name_ja": "上海",
  "script": "hans",
  "reading_lang": "cmn",
  "center": [31.23, 121.47],
  "zoom": 12,
  "focus_bbox": [31.16, 121.42, 31.27, 121.54],
  "source": { "name": "OpenStreetMap", "extracted": "2026-10-04" },
  "lines": [
    {
      "id": "2",
      "ref": "2",
      "name_orig": "2号线",
      "name_ja": "2号線",
      "color": "#RRGGBB",
      "stations": ["sh_lujiazui", "sh_nanjingdonglu"],
      "geometry": [[[31.2, 121.5], [31.21, 121.49]]]
    }
  ],
  "stations": [
    {
      "id": "sh_lujiazui",
      "name_orig": "陆家嘴",
      "name_ja": "陸家嘴",
      "reading": { "roman": "Lùjiāzuǐ", "kana": "ルージャーズイ" },
      "name_en": null,
      "lat": 31.0,
      "lon": 121.0,
      "lines": ["2", "14"],
      "verified": true
    }
  ]
}
```

補足：
- `script` は `hans`（簡体字）または `hant`（繁体字）。`reading_lang` は `cmn`（普通話）または `yue`（広東語）。
- `focus_bbox` は主要エリア（南・西・北・東）。上海の値は初期値で、調整してよい。
- `geometry` は折れ線の配列（支線や環状線に対応するため複数本を許す）。座標は [緯度, 経度]。
- `stations` の順序は路線の駅順。支線がある路線は、本線と支線を分けて持てる構造にしてよい（その場合は README に構造を書く）。
- `verified` は、表記と読みを人が確認済みかどうか。未確認の駅は画面上でも区別できるようにする（薄い印など）。
- 上のサンプルの色と座標は仮の値。

## 6. データ作成の手順

### 6.1 取得
- 出典は OpenStreetMap に統一する。Overpass API から、都市ごとに地下鉄の路線リレーション（`route=subway`。香港は `light_rail` を含めるか README で判断を示す）と、その構成要素（線路と駅）を取得する。
- 参考のクエリ（行政区の指定方法は都市ごとに確認して直すこと）：

```
[out:json][timeout:180];
area["name"="上海市"]["boundary"="administrative"]->.a;
relation["route"="subway"](area.a);
out body;
>;
out geom qt;
```

- 取得した生データは `raw/` に保存し、再取得せずに加工をやり直せるようにする。

### 6.2 加工
1. 上り・下りで別リレーションになっている路線を 1 路線にまとめる。
2. 路線番号（`ref`）、路線名、色（`colour`）を取り出す。色が欠けている路線は運営会社の公式色で補い、補った旨を記録する。
3. 駅を抽出し、駅名末尾の「站」を除く。同じ駅が路線ごとに別の点になっている場合は 1 駅に統合し、所属路線を集約する。
4. 駅名を日本の漢字表記に変換する（OpenCC の簡体字→繁体字→日本新字体）。1 対多の字（发、汇、干、面、后、里など）は誤変換が出るので、上書き辞書 `overrides/` で直せるようにする。
5. 読みを付ける。普通話はピンイン変換ライブラリ（pypinyin など）、広東語は粤拼の変換ライブラリを使う。多音字と地名の例外は上書き辞書で直す。カタカナは音節の対応表から機械的に作る。
6. 付録 A の確認済みデータで上書きし、機械変換の結果と食い違った駅を一覧で出力する（変換規則の改善に使う）。

### 6.3 検証
- 路線数と各路線の駅数を、運営会社の公式路線図または Wikipedia の駅一覧と照合し、差分を出力する。
- 駅の点が自路線の線形から大きく離れていないかを確認する。
- 駅名の改称に注意する（上海では 2024 年に 东昌路→浦东南路、浦东国际机场→浦东1号2号航站楼 などの改称があった）。OpenStreetMap の現行名を正とし、公式路線図と食い違えば報告する。
- 上海は 2026 年 12 月末に 21 号線の開業が予定されている。データに開業前の路線が混ざらないよう、取得日時点で営業中の路線だけを採る。

### 6.4 座標系
OpenStreetMap の座標（WGS-84）だけを使う。高徳地図や百度地図に由来するデータは座標系が異なり、混ぜると数百メートルずれるので使わない。

## 7. 技術構成

- 表示ページ：静的ファイルのみ（`index.html`、`app.js`、`style.css`、`data/*.json`）。地図ライブラリは Leaflet を想定。ビルド工程は設けない。
- データ作成：Python 3 のスクリプト。Windows で動くこと（パスは pathlib、文字コードは UTF-8 を明示）。依存ライブラリは `requirements.txt` に書く。
- ローカル確認：`python -m http.server` で開けること。
- 公開：静的ホスティング（GitHub Pages など）にそのまま置ける構成にする。公開するかどうかは利用者が決める。
- 出典表示：画面に「© OpenStreetMap contributors」と地図タイルの出典を表示する。

## 8. 段階

1. 上海（全路線・全駅）と表示ページ一式。主要エリアの 64 駅は付録 A で確認済みにする。
2. 広州、深圳。
3. 香港（広東語の読み、英語名の保持）。
4. 任意：駅名を隠して確かめる学習モード。表記変換と読み付与の部品を、文章を貼り付けて変換する別ページでも使えるように切り出す。

各段階の終わりに、検証結果（6.3）と未確認の駅数を報告すること。

## 9. 受け入れ条件

- 上海の営業中の全路線が、公式色の線で、実際の線形に沿って表示される。
- 駅にホバーまたはタップすると、原表記・日本の漢字表記・読み（ローマ字とカタカナ）・路線バッジが出る。それ以外の情報は出ない。
- 乗換駅は 1 点で、通る路線がすべてバッジに出る。
- 付録 A の 64 駅の表記と読みが、付録どおりに表示される。
- 都市の追加が、`data/` へのファイル追加と `cities.json` への 1 行追加だけで済む。
- iPhone の Safari で、タップによる表示、拡大縮小、都市切替が使える。
- 緯度・経度が画面に出ない。旅行固有のデータが含まれない。

## 10. 未確定事項と前提

- 置き場所：未定。ローカルでも静的ホスティングでも動く構成にしておく。
- リニア（磁浮）と空港連絡線などの地下鉄以外の路線：第 1 段階では対象外。含める場合は路線種別を区別できるようにする。
- 香港のカタカナ：日本語で定着した呼び名がある駅は、上書き辞書で指定できるようにする。
